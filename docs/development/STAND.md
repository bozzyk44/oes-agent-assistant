# Стенд в облаке

Как создать и удалить сервер стенда. Что это за сервер и почему он такой — в [INFRASTRUCTURE.md](../architecture/INFRASTRUCTURE.md) и решении 9 в [DECISIONS.md](../architecture/DECISIONS.md).

Стенд — дополнение к локальному запуску. Для проверки задания он не нужен.

## Что нужно

- Docker. Terraform ставить не надо: он запускается в контейнере.
- В `.env` в корне репозитория: `CLOUD_RU_KEY_ID`, `CLOUD_RU_KEY_SECRET`, `CLOUD_RU_PROJECT_ID` — ключ сервисного аккаунта Cloud.ru и идентификатор проекта.
- Публичный SSH-ключ. По умолчанию берётся `~/.ssh/id_ed25519.pub`; другой путь задаётся переменной `STAND_SSH_PUBLIC_KEY_FILE`.

## Команды

Из корня репозитория:

| Команда | Что делает |
|---|---|
| `infra/terraform/tf.sh init` | Скачивает провайдер. Нужна один раз |
| `infra/terraform/tf.sh plan` | Показывает, что будет создано |
| `infra/terraform/tf.sh apply` | Создаёт стенд: около трёх минут, плюс две минуты на первую настройку сервера |
| `infra/terraform/tf.sh output` | Адрес сервера, команда входа, адрес сервиса |
| `infra/terraform/tf.sh destroy` | Удаляет всё созданное: около двух минут |

## Что создаётся

| Ресурс | Параметры |
|---|---|
| Группа безопасности | Входящие: SSH и порт сервиса. Исходящие: любые |
| Загрузочный диск | SSD, 30 ГБ, Ubuntu 24.04 |
| Сетевой интерфейс | В подсети проекта по умолчанию |
| Публичный IP | Один |
| Сервер | 2 vCPU с долей 10 %, 4 ГБ |

При первом запуске сервер сам ставит Docker, Compose, make и git и создаёт пользователя с входом по ключу. Развёртывание самого сервиса сюда пока не входит: оно добавится, когда появится compose.

## Что проверено

Полный цикл на живом облаке, 2026-10-13: создание восьми ресурсов, вход по SSH, запуск контейнера, доступ с сервера к ИИ-роутеру, удаление с проверкой через API, что в проекте ничего не осталось.

Группа безопасности проверена снаружи: временный веб-сервер на порту сервиса отвечал, такой же на порту PostgreSQL — нет.

## Особенности провайдера

То, на чём споткнулась первая версия конфигурации.

1. **Провайдера нет в общем реестре Terraform.** Он ставится с зеркала Cloud.ru; адрес зеркала — в `infra/terraform/terraform.rc`, скрипт подключает его сам.
2. **Нет сборки провайдера под linux/arm64.** Контейнер с Terraform всегда запускается как amd64; на машинах с ARM — через эмуляцию, поэтому команды идут заметно медленнее.
3. **Порт в правиле группы безопасности задаётся диапазоном**, даже если он один: `22:22`. Одиночное значение провайдер принимает, но затем сообщает о несогласованном результате.
4. **Серверу нельзя передать одновременно метаданные образа и cloud-init.** Пользователь, ключ и имя хоста заданы в cloud-init.
5. **Каждая операция с ресурсом занимает около тридцати секунд**, даже удаление правила.

## Состояние Terraform

Файл состояния лежит локально в `infra/terraform/` и в репозиторий не попадает. Для стенда, который создаёт один человек, этого достаточно. Если стенд создаётся с другой машины, состояние придётся перенести или удалить стенд с той же машины, где он создан.

Ключ сервисного аккаунта в состояние не записывается: провайдер читает его из окружения.
