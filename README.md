# Ассистент сотрудника с правами доступа

Тестовое задание на позицию Tech Lead (корпоративные ИИ-агенты). Сервис для вымышленного рудника АО «Северная руда»: агент на LLM отвечает сотрудникам по регламентам и показателям и готовит заявку на ремонт оборудования. Задание — в [docs/business/TASK.md](docs/business/TASK.md).

Четыре правила, которые сервис обязан соблюдать:

1. **Права.** Агент видит только то, что видит пользователь; проверяет код, а не промпт.
2. **Бюджет.** Лимит вызовов модели и токенов соблюдается при сборке входа.
3. **Запись.** Заявка создаётся только после подтверждения и ровно один раз.
4. **Измеримость.** Качество, утечки и стоимость измеряются прогоном по эталонным вопросам.

## Состояние

Работа начата. Есть каркас: образ, запуск одной командой, тесты и локальный CI. Есть генератор набора и три шага перед сервисом: создание ролей и баз, миграции и загрузка набора из `DATA_DIR` в PostgreSQL. Сервис отвечает на `POST /turn` агентным циклом поверх OpenAI-совместимого API: пять инструментов, права через слой доступа, итог в формате задания, история сессии; запись хода — `GET /turns/{turn_id}`, сведения о сборке — `GET /info`. Бюджет хода проверяется до отправки каждого вызова: не больше четырёх вызовов, 8 000 токенов входа на вызов и 24 000 на ход по локальной оценке с поправкой по фактическому расходу; результат инструмента во входе — не больше 1 500 токенов. Заглушка ТОиР принимает заявки с ключом идемпотентности и отдаёт их список. Подтверждение и отказ работают: заявка уходит в ТОиР только после подтверждения автором и ровно один раз, включая повтор и рестарт; черновик предлагает агентный цикл. Этот файл дополняется по мере работы: что сделано и что сознательно не сделано, затраченное время, раздел «Работа с ИИ».

## Запуск

Для четырёх команд задания нужны только Docker и make. Проверено на Docker Engine 29 и Compose 5; файл compose использует `start_interval`, которому нужен Engine не старше 25.

| Команда | Что делает |
|---|---|
| `make run` | Создаёт `.env` со случайными секретами, если его нет, и поднимает PostgreSQL, шаги ролей, миграций и загрузки набора, сервис и заглушку ТОиР. Сервис — на `http://127.0.0.1:8000` |
| `make reset` | Останавливает и удаляет том базы. Нужна, если `.env` создан заново: пароль администратора PostgreSQL запоминается в томе |
| `make test` | Линтер, типы и тесты; без сети и без модели |
| `make data` | Пишет набор в `data/` — пользователей, три таблицы КХД, документы и эталонные вопросы — и проверяет формат и состав, в том числе что строки `forbidden` не встречаются в данных автора вопроса; при нарушении завершается ошибкой. Зерно постоянное: повторный запуск даёт те же файлы |
| `make data-holdout` | Тот же генератор с другим зерном в `holdout/`: набор для итоговой проверки, на котором промпт не настраивался |
| `make eval QUESTIONS=<путь>` | Прогон эталонных вопросов по запущенному `make run` сервису: каждый вопрос `EVAL_ATTEMPTS` раз (по умолчанию 3) в своих сессиях; пишет `eval/results.jsonl` и `eval/report.md`. По умолчанию — `$DATA_DIR/questions.jsonl`. С настоящей моделью — платно |
| `make eval-report` | Пересобирает `eval/report.md` из `eval/results.jsonl` без сервиса |
| `make eval-compare A=<прогон> B=<прогон>` | Сравнивает два прогона из `eval/runs/` попарно по вопросам; конфигурации должны отличаться ровно в одном поле |
| `make mutants` | Прогон против сборок сервиса с одной отключённой защитой — доказательство, что набор ловит нарушения; таблица — `eval/mutants/mutants.md`. По умолчанию со сценарной заглушкой модели; `MUTANT_MODE=model` — с настоящей моделью, платно |
| `make migrate` | Применяет миграции к базе текущего запуска; `make run` делает это сам, отдельным шагом перед загрузкой набора. Если PostgreSQL не запущен, поднимает его и оставляет работать; остановить — `make down` |
| `make ci` | Проверка миграций, `make test` и сценарий сборки на чистой копии текущего коммита; нужны ещё git и tar |

Модель задаётся переменными `MODEL_BASE_URL`, `MODEL_API_KEY`, `MODEL_NAME` — в `.env` или в окружении оболочки. Обязательны адрес и имя; ключ можно оставить пустым, если серверу модели он не нужен. Модель на той же машине, например Ollama, указывается как `http://host.docker.internal:11434/v1`: `localhost` внутри контейнера — это сам контейнер. На Linux без Docker Desktop это имя ведёт на адрес моста Docker, а не на `127.0.0.1` хоста, поэтому модель должна слушать не только локальный адрес: для Ollama — `OLLAMA_HOST=0.0.0.0`. Контекст модели должен вмещать вход до 8 000 токенов и выход: у Ollama — `num_ctx` не меньше 10 240, у vLLM — `--max-model-len`. Иначе Ollama молча обрежет вход, а vLLM отклонит запрос. Необязательные `MODEL_MAX_OUTPUT_TOKENS`, `MODEL_TIMEOUT_SECONDS`, `MODEL_RESPONSE_FORMAT` (`last`, `all`, `off`), `MODEL_EXTRA_BODY` (JSON, добавляется к телу запроса — например, чтобы выключить рассуждения модели) и `MODEL_TOKEN_CHARS` (символов на токен для оценки входа) описаны в `.env.example`. Свой набор данных — переменной `DATA_DIR`.

Имя проекта compose одно на машину: второй клон репозитория делит с первым контейнеры и том базы. Чтобы развести их, задайте `COMPOSE_PROJECT=<имя>` при вызове `make`.

## Как ведётся работа

Сначала документ, потом код. До первой строки кода записаны решения с отвергнутыми вариантами, лимиты инфраструктуры и задачи с критериями приёмки. ИИ-агент пишет код по этим документам и по задаче, а не по устному пересказу; результат принимается по критериям из задачи, тестам и ревью.

|---|---|
| Решения и условия их пересмотра | [docs/architecture/DECISIONS.md](docs/architecture/DECISIONS.md) |
| Устройство кода: права, запись, бюджет хода, API | [docs/architecture/ARCHITECTURE.md](docs/architecture/ARCHITECTURE.md) |
| Что видит модель: состав входа, инструменты, формат ответа | [docs/architecture/AGENT.md](docs/architecture/AGENT.md) |
| Поиск: почему без векторов, когда они нужны, что измерять | [docs/architecture/RETRIEVAL.md](docs/architecture/RETRIEVAL.md) |
| Чем доказана каждая гарантия | [docs/development/TESTING.md](docs/development/TESTING.md) |

| Процедуры для ИИ-агента: путь задачи до PR и независимое ревью | [.claude/skills/](.claude/skills/) |
| Задачи с критериями приёмки | [Issues](https://github.com/bozzyk44/oes-agent-assistant/issues) |

Каждая задача идёт своей веткой: черновик PR, локальный CI, ревью агентом кругами до круга без существенных находок, перевод PR в готовые, ревью человека, squash-merge. Первый коммит с документами сделан напрямую в `main`, дальше — только через PR.
